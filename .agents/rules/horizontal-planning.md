# Horizontal Planning: Deep Conceptualization Gate ## Philosophy To ensure architectural integrity in the CMV2 engine, we prioritize "T-Shaped" development. This means solidifying horizontal domain contracts (Layer 1) across all modules before deepening vertical implementations (Layer 2). ## Strict Planning Rules 1. **Diagrams Before Code**: No implementation code (Layer 2) or finalized Layer 1 Pydantic/SQL models may be written until a **DEEP conceptualization using diagrams** (Mermaid or D2) has been created and approved. 2. **Horizontal Breadth First**: When addressing a domain (e.g., Action Mechanics), the focus must remain on the cross-module interface and data schema horizontally before a single feature is implemented vertically. 3. **Rationale Prerequisite**: Every Layer 1 Contract must be accompanied by an architectural rationale in `ISSUES/architecture/system_info/` explaining the "Why" and the legacy harvesting strategy. 4. **No Early Refactoring**: Do not refactor existing "Gold" or "Silver" code to match a developing contract until the conceptual diagrams for that contract are frozen. ## Activation - **When to apply**: Active for all tasks involving folders in `ISSUES/architecture/01_contracts/`. - **Activation Strategy**: Always On.
